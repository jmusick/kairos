# APL replay: Arcane Sunfury, 12.1.5 (70575)

- **Date:** 2026-10-30
- **Data:** dummy sessions in one combat log (`WoWCombatLog-103026_110311.txt`) plus the flight recorder (Assisted Combat's picks)
- **APL:** `Kairos/Specs/MageArcane/APL.lua`, from SimC `midnight` at `515f4a3fe9`: the cooldowns list plus the Sunfury list. Sessions 1 to 6 were scored with the hand-written version; the generated module that replaced it makes the same picks on all of them. The line names in the tables below are the hand-written labels. The generated ones read `sunfury:arcane_barrage (1/3)` (the line and which top-level `|` clause fired), and `apl` prints what each stands for. Off-GCD Touch of the Magi, potions, racials, trinkets and Counterspell are left out.
- **Command:** `tools/kairos-dump.lua apl <log> <Kairos.lua> Merlinmonroe [from [to]] [verbose]`

## Method

The replay rebuilds the true Arcane state from the combat log and, at every decision, compares four picks:

1. **APL on true state:** what Kairos should show (SPEC §9's reference pick).
2. **Kairos:** the same APL with the Salvo and Cumulative Power estimators' values in place of the true stacks. Everything else is true state, so the gap between 1 and 2 is the estimators alone. The report also shows each estimator on its own.
3. **Assisted Combat:** Blizzard's pick at that moment, from the flight recorder. 375 of 429 recorded casts aligned to the log within 0.1 s.
4. **The player's cast.**

A decision is each cast on the GCD, taken at `SPELL_CAST_START` for cast-time spells (Arcane Blast, Prismatic Bolt) and at `SPELL_CAST_SUCCESS` for instants and channels. While the Prismatic Bolt proc is up, a Blast pick counts as Bolt (same button).

True state from the log:

| Input | Source |
|---|---|
| Salvo, Clearcasting, Cumulative Power stacks | Aura events (`APPLIED`, `DOSE`, `REMOVED`) |
| Arcane Soul, Arcane Surge buff, Prismatic Bolt proc (`1295942`) | Aura events |
| Arcane Charges | `SPELL_ENERGIZE` power type 16; Barrage spends all |
| Touch, Surge, Orb cooldowns | Own casts: 45 s, 90 s, 2 charges at 20 s (probe values, no haste or reductions) |
| Enemies | Distinct creatures the player damaged in the last 3 s |
| Talents and set bonus | Inferred: Spellfire Sphere procs mean `spellfire_spheres`; Cumulative Power means the Season 2 4-piece; Arcane Pulse was never cast, so it's treated as not talented |

## Caveats

- **Only Salvo and Cumulative Power are estimated in the Kairos column.** In game, more inputs are secret or modeled: cooldowns (timed from casts), Clearcasting (presence only, through the Missiles glow), the Prismatic Bolt proc (readable through its glow), Arcane Soul (timed from Surge) and the enemy count. The real in-game number will be lower until each has a model in the replay.
- **The true state is itself reconstructed.** The log writes a buff's removal a few ms after the cast that consumed it, so the replay applies Barrage's Salvo consumption and Blast or Bolt's Cumulative Power consumption at the cast. Cooldowns ignore haste and any reductions, enemy count is "damaged in the last 3 s", and Lustrous Gleam is assumed absent (never seen).
- **The APL hasn't been checked against SimC itself.** It's generated now (D21), and the generated and hand-written translations agree with each other, but neither has been compared with picks from a SimC run.
- **Dummies only.** Single target and cleave dummies, no movement-heavy or multi-target pulls.

### Scoring corrections found during review

The initial report showed 83/111 live matches (75%). Two offline timing errors
were responsible for part of that shortfall:

1. `GetTime()` can give a Bolt success, a Barrage success and the new post-Barrage
   pick the same timestamp. A constant clock offset can then place that new pick
   a few milliseconds before the log's Barrage success, grading the wrong pick.
   The scorer now matches ordered recorder casts to log successes and excludes
   picks at or after that cast entry. Cast-time decisions still use their start
   time. This changes the live score to 93/111 (84%).
2. Barrage generates its Bolt proc before its `SPELL_CAST_SUCCESS` line is printed.
   For example, the opening Bolt proc appears at 18:31:02.583, four milliseconds
   before the Barrage that generated it. The scorer now treats a newly applied
   Bolt proc within 10 ms before Barrage success as an effect of that press, not a
   pre-press alternative. It remains available to subsequent decisions. Twelve
   such events were identified; the correction changes five live comparisons.
   A proc already available earlier remains in the pre-press state.

These are offline scoring changes, with regression tests for clock coalescing,
post-cast pick exclusion, cast-start sampling and causal proc ordering. They do
not change generated priorities, live picks or either estimator's gains. The
10 ms rule is a build-specific ordering assumption, grounded in these logs and
the pinned Mage implementation's Barrage proc; the command prints its count.
